# Phase P4 — Review renderer & consoles

**Size L · ~14–16 nights · proves: the Sunday review exists as code, and its
anti-fabrication gates fire.**

One generated document per ISO week, two layers, gates before paint. The
mechanical layer has **zero agent dependency** — it survives every cron
being dead (09 §2 preamble; proven empirically by the W37 dry-run).
Narration is an enhancement layer, never a dependency (09 §3). Both
consoles are read-models; the only vault-writing code in the entire app
lives in `staged_writebacks/` (02 §6).

**Ships:** mechanical renderer (8 fixed sections, five coverage states) ·
staging checker (gates 1+4 enforced, 2–3 stubbed to their data) · staged
vault export with write-back provenance · W41 draft exit · narrated pass
scaffold · goal derivation pass · agents screen (incl. the Multica
read-through P1 deferred here) · server screen. **Not here:** agent chat
and assignments ship P4.5 (02 §3) — `PHASE-P4.5-LIFE-CONSOLE.md`.

**Entry:** P3 exit (nutrition re-ingest test green, demoted strip renders
muted, reading queue seeded).

**Exit** (EXECUTION Part II, P4 row; 02 §5 P4 row):
- W41 draft generates **mechanical-only** and exports to the vault
- numeral-diff gate **demonstrably rejects one fabricated stat**
- narrated pass upserts; provenance edges resolve
- sections-never-disappear proven on an all-empty fixture
- server screen proven read-only (no restart action exists in the tree)

**Rollback:** T1 on the artifact plane — a bad week is regenerated by
re-export, never hand-patched (09 §1: the record is the row, not the
path). T2 on `app/` code. A wrong write-back self-corrects by
regeneration plus a fresh `write-back` provenance edge; no DELETE, ever.

**Descope order (EXECUTION Part IV):** server screen (htop exists) →
goal derivation (the horizon can wait a phase) → narrated scaffold
(mechanical still ships). **Never cut:** the numeral-diff gate — it is the fabrication
defence, and it is also the cheapest thing here (~200 lines).

**Read before starting:** `docs/plan/v1/09-weekly-review-format.md` in
full — this phase is its renderer · `02-architecture.md` §5 P4 row + §6
(numeral traceability, fresh evidence floor, single-writer statuses) ·
`08-agent-console.md` §20–21 · `01-design-system.md` (Week screen row,
ink-pair state colors, hue law §4) · `04-screens-pwa.md` (§/week,
§/agents + /server) · `docs/dry-run/2026-W37-dry-run.md` (empty-month
ground truth; source of the fifth render state).

## The rule that governs every task in this phase

**The review states its evidence base before claiming anything, and no
number renders that the mechanical export did not produce.** Coverage
block first, always (09 §2#1). Every rendered numeral is traceable:
event → mechanical doc → numeral-diff gate (02 §6). A gate failure
blocks the write-back **before the file is touched** (09 §3). Sections
never silently disappear — an empty section renders its coverage line.
The grep that must stay green all phase: vault write paths exist in
exactly one module, `staged_writebacks/` (02 §6).

## Five render states (09 §2#1 as amended by W37 finding #2)

| State | Obsidian callout / tier | When it fires |
|---|---|---|
| alive | `[!success]`, green pair | source passes its success predicate (law 1) |
| dead | `[!failure]`, red pair | **system failure only** — a human must fix |
| paused | `[!warning]`, amber pair | recorded `job_paused` event, actor=human (law 5) |
| behavioral muted | muted gray — never a state hue | meals/wake dormancy (law 4 classes; dormancy law) |
| uninstrumented | neutral note, never alarms | awaiting first data (wake pre-P0, reading pre-P3) |

The fifth state is the W37 dry-run's delivered defect: the four
dormancy-law states do not cover "not yet instrumented". It renders
neutral and stays Dataview-visible (frontmatter `coverage` map, 09 §4).
One-line 09 amendment proposed at next touch; P4 implements it now.

### T4.1 — Mechanical renderer

**Reads:** `09 §2` (all eight rows) · `09 §4` (file skeleton) ·
`02 §2` laws 7, 11 · `01 §1` state pairs · `04` §/week ·
`docs/dry-run/2026-W37-dry-run.md` (the render block is the fixture)
**Depends on:** P3 exit
**Parallel with:** T4.4, T4.5
**Tier:** T2 (app code); the artifact it emits rolls back at T1 (re-export)

**Build** `app/review/renderer.py`: a pure function week → document.
Eight sections in the fixed order of 09 §2#1–#8 — coverage block ·
plan vs actual · tasks & loops · habits · wellness · reading &
research · activity digest · carry-forward — emitting the 09 §4
skeleton: frontmatter (`week`, `layer`, `generated_at`, `coverage`
map) and the `# Week NN · ISO-range` header.

- **Coverage block always first**, lines from the one shared
  `coverage` view (law 7): "day reports 5 of 7 · digest alive
  (repaired Oct 2) · meals 0 of 7 (dormant since Aug 16)". Each source
  line maps to one of the five render states (table above).
- **Sections never disappear.** A section with no data renders its
  coverage line — branching on data presence to skip a section is the
  defect this task exists to make impossible (09 §2 close; W37
  finding #4).
- Missing days render missing, never zero (law 7). Recall ticks render
  `~`. Estimates render `~` with provenance to their basis (law 11).
- Habits: rolling windows only ("wake within ±30 min: 4 of 7"), no
  streaks anywhere in the data model of the section (09 §2#4).
- Wellness headline rule: after ≥14-day dormancy the first covered
  week renders "restart confirmed" — never a trend; trends locked
  until two covered weeks exist (09 §2#5).
- Activity digest carries the ops line (service up/down/restart counts
  from spine presence events) (09 §2#7).
- **Numeral manifest:** every numeral the renderer emits is recorded in
  a `sections` JSON side-structure stored on the `document` row (schema
  v0.1 already carries it). This manifest is gate 1's right-hand side —
  one extractor, two consumers (renderer writes it, checker reads it).
- Week screen renders the document on the torn-paper sheet, serif,
  65ch measure; ink-pair state dots for coverage; **plum left-rule only
  on narrated sections**; zero accent in body text (01, Week screen
  row; 01 §4 hue law).

**Tests** `app/tests/review/test_renderer.py`
- All-sources-alive fixture → 8 sections in fixed order, coverage block first
- All-empty fixture (W37 shape) → still 8 sections, each a coverage
  line; assert every `##` header present
- Five states: alive/dead/paused/behavioral-dormant/uninstrumented map
  to the five callout tiers; behavioral dormancy never renders a state
  hue (01 §1)
- Numeral manifest equals the set of numerals in the rendered body —
  same extractor, asserted both directions
- No `agent_invoke` import reachable from the renderer module (grep in CI)
- Week screen snapshot: serif paper surface, plum rule absent on all
  mechanical sections

**Done when**
- [ ] W37 fixture re-renders matching the dry-run's hand render (modulo timestamps)
- [ ] Empty fixture keeps all eight sections; coverage line per empty section
- [ ] Numeral manifest round-trips against the rendered body

**If it fails**
A section that vanishes when its source is empty means the renderer
branches on data presence — render coverage unconditionally. Red on
behavioral dormancy means the state mapping used the dead tier —
dormancy is muted by design (01 §1; 02 §6). A numeral in the body but
not the manifest means a section is formatting its own numbers instead
of reading them from the section data — fix the section, never widen
the manifest after the fact.

**Commits**
`chore(T4.1): start mechanical-renderer — baseline green` →
`feat(T4.1): mechanical renderer, eight fixed sections, five coverage states`

### T4.2 — Staging checker (gates 1 + 4; 2–3 stubbed)

**Reads:** `09 §3` (gates 1–4) · `02 §6` (numeral traceability, fresh
evidence floor) · `W37 finding #5` (gates' first real test is the first
narrated pass with ≥1 covered week)
**Depends on:** T4.1
**Parallel with:** T4.3, T4.4, T4.5
**Tier:** T2

**Build** `app/review/checker.py`: runs inside the staged write-back,
before any file is touched. Input: narrated text + the mechanical
export's numeral manifest. Output: pass, or a rejection naming the
offending strings.

- **Gate 1 — numeral-diff (live).** Extract numerals from the narrated
  text, normalize both sides (digit words "five"≡"5"; "5 of 7" forms;
  weekday/month names), require membership in the manifest. Fabricated
  or rounded stats fail staging. This is the assert/quote split as a
  gate, not a style guide (09 §3.1).
- **Gate 4 — lexical (live).** Banned vocabulary by string match:
  "streak", "scoreboard", "cheat", plus the moralized-evaluatives list
  ("perfect week", "kept the streak alive", …). Behavioral facts are
  narrated descriptively — "ticked 2 of 4 planned"; evaluative status
  words belong to goals only (09 §3.4). Substring match catches
  inflections; accepted v0 false-positive cost.
- **Gates 2–3 — stubs to their data.** Evidence floor (pattern claims
  need ≥4 weeks with ≥5 covered days; 09 §3.2) and temporal gate
  (`context_note` quotable for W iff its validity window intersects W;
  09 §3.3) implement their full signatures and return
  `inactive: awaiting accumulated weeks`. They activate the first week
  the data exists — no rework, no schema change (02 §6 fresh-evidence
  floor shapes gate 2's signature now).

**Tests** `app/tests/review/test_checker.py`
- Narration containing "wake 6 of 7" against a manifest that holds
  "4 of 7" → gate 1 rejects, names the numeral
- "five of seven" normalizes to match "5 of 7" → passes
- "streaks" (inflected) → gate 4 rejects by substring
- "perfect week" on behavioral data → rejects
- Gates 2–3 stubs return inactive-with-reason and never block
- A gate failure blocks before any vault write — assert no temp file
  and no `write-back` edge on rejection

**Done when**
- [ ] Fabricated-stat rejection demonstrated (the P4 exit test's core)
- [ ] Normalized equality proven ("five of seven" ≡ "5 of 7")

**If it fails**
If a fabricated number passes, the two sides ran different extractors —
gate and renderer must share one (T4.1's manifest is the contract).
Never make a failing gate pass by loosening matching: no fuzzy
fallbacks on gate 4 — string match is the enforcement (09 §3.4), and a
gate that can be argued with is not a gate.

**Commits**
`chore(T4.2): start staging-checker — baseline green` →
`feat(T4.2): numeral-diff and lexical gates, evidence and temporal stubs`

### T4.3 — Staged export to vault

**Reads:** `09 §1` (identity & storage) · `02 §2` law 6 · `02 §3`
(`document` table, frozen v0.1) · `02 §6` (no vault writes outside
`staged_writebacks/`)
**Depends on:** T4.1
**Parallel with:** T4.2, T4.4, T4.5
**Tier:** T2 code; wrong write-back self-heals by regeneration + fresh

**Build** `staged_writebacks/review_export.py`:
- Writes vault `Eudaimonia/Reviews/<ISO-week>.md` (e.g.
  `2026-W41.md`); `document.path` records it. Movable during build —
  the record is the row, not the path (09 §1).
- `document` rows upsert on `UNIQUE(kind, week_id, layer)` (frozen
  v0.1): `ON CONFLICT ... DO UPDATE`. Mechanical writes first
  (`layer='mechanical'`); the narrated pass later re-exports the
  composed file (T4.7).
- Every apply logs a **`write-back` provenance edge** (law 6). Export
  order: mechanical first, narrated re-export second.
- Atomic apply: temp file + rename; a crash mid-apply leaves the old
  or the new file, never a partial one.
- The file is an export; app state lives in SQLite, never the reverse
  (law 6). CI grep: vault write paths in exactly one module.

**Tests** `app/tests/review/test_export.py`
- Export → file at the exact vault path + one `document` row
  (kind, week_id, layer)
- Re-export same week → row count still 1 (upsert), file replaced,
  **second** `write-back` edge appended (the edge log grows; rows don't)
- Provenance edge resolves: mechanical document ref ↔ write-back event
- Kill a writer mid-apply (fault injection) → old file intact, no
  partial content
- Grep gate: no vault-path writes outside `staged_writebacks/`

**Done when**
- [ ] Re-export proven idempotent on `UNIQUE(kind, week_id, layer)`
- [ ] Write-back provenance edge round-trips

**If it fails**
Duplicate rows mean the insert isn't targeting the UNIQUE conflict —
fix the `ON CONFLICT` clause, never add a find-then-insert prequery
(race by construction). Vault drift from hand edits is expected and
harmless: next Sunday's regeneration overwrites; the row is the record.

**Commits**
`chore(T4.3): start staged-review-export — baseline green` →
`feat(T4.3): staged vault export, UNIQUE(kind, week_id, layer) upsert, write-back edges`

### T4.8 — Goal derivation pass + `/goals` horizon

**Reads:** 07 §19 (goals; derived status; the evidence-freshness floor) ·
02 §6 (single-writer statuses; fresh-evidence floor; failure never reads
as success) · 02 §2 law 1 (freshness ≠ success), law 5 (human-only
parked), law 7 (coverage honesty) · 01 §1 (state pairs; paper tier) ·
04 `/goals` · 06 colour row (Goals)
**Depends on:** T4.1 (the spine queries and coverage block it reuses),
P3 exit (T3.4's engine supplies source freshness)
**Parallel with:** T4.4, T4.5
**Tier:** T2 (the pass is `app/` code); a wrong status self-corrects on
the next pass — the cache is derived, never authored

**Build**

A derivation pass plus the `/goals` horizon list. The `goal` table exists
from migration 001 (T0.2 Section 2: title, target_date, status CHECK,
links JSON).

**[impl] `goal.status` has exactly one writer: this pass** (02 §6;
07 §19 amendment (b)). Every transition emits a `goal_status_derived`
event **first**, then updates the row as a materialized cache — so a
wiped entity table rebuilds identically from the spine (EXECUTION §1).
There is no status editor, no admin endpoint, and no hand-edit path;
`parked` is the one exception and it is **human-only** (law 5), arriving
as its own actor=human event, never from derivation.

**[impl] Derivation inputs and rule** (07 §19): `at-risk` when linked
overdue work exceeds the threshold, or the target date passes without
`achieved`; `achieved` on its recorded evidence; `on-track` otherwise.
Linked work resolves by payload query (`goal_id` in event payloads —
07 §19 amendment (a); no frozen columns, 02 §6). Progress renders as an
evidence summary from the spine ("12 tasks closed since Aug · dMAT
registered ✓"), never a percentage.

**[impl] The fresh-evidence floor is the load-bearing rule** (02 §6;
07 §19, from the wellness seat). The pass computes **only** from sources
passing their freshness predicate. When the evidence base is stale, the
